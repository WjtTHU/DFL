## 时间与信息规则

| 集合 | 日期范围 | 执行评价期数 T | 含规划延伸的需求期数 |
| --- | --- | ---: | ---: |
| 训练 | 2024-10-01 至 2024-12-30 | 13 | 16 |
| 验证 | 2024-12-31 至 2025-01-27 | 4 | 7 |
| 测试 | 2025-01-28 至 2025-03-17 | 7 | 10 |

采用 Asia/Shanghai 本地时间，每期 7 天、规划 N=4 期。每周二 00:00 做决策，输入只使用此前已经可见的记录，等价于前一天日末预测；例如测试第 1 次决策是 2025-01-28 00:00，对应预测日期 2025-01-27。最后 3 周额外需求只用于规划展望，不加入 T 期执行评价。

第一货源订单从首次快照出现时进入可见集合；没有真实订单 release time，不将首次观测伪称为合同释放或真实开工时间。决策输入包含当时可见且尚未发生模拟到货的 root Lot。未来新出现的 Lot 单独保存为外生事件，在出现前不得读入订单集合。历史窗口保留 15 天内全部日内观测，窗口无记录时沿用最后一条真实旧记录并标记过时，不伪造新快照。

当期第一货源到货只能在下一期用于生产。模拟中已发生的整批到货视为可观测事件；企业标签的 3 天缓冲是离线完工确认要求，不作为运输或收货延迟。`inputs` 不包含未来完工时间；`replay` 的完整记录只能由回放程序按事件时间读取，不能整体交给预测器。`labels` 另存截止时可用的标签，训练标签必须在 2024-12-31 前可用，验证标签在 2025-01-28 前可用，测试标签在原始数据截止前可用。回放里的事后推定到货记录不是训练标签。

三个集合分别初始化，只在轨迹起点给一次原材料库存、成品库存、积压及第二货源在途状态。后续状态由未来滚动执行程序产生，本次不逐期随机生成状态，也不把三条片段描述为连续运营。边界已可见且尚未到货的 Lot 保留为初始第一货源在途订单。

CSV 使用 UTF-8 BOM，时间为无时区后缀的 Asia/Shanghai 本地时间；区间左闭右开。缺失的完工标签、预测值及未确认实际到货不是数值 0。

`shared/observations.csv` 含跨集合历史，不能整表输入预测器。应通过 `load_decision(dataset_dir, split, period)` 读取某个决策时点，只返回当时可见订单、相应历史及 4 期需求/产能。该函数不读取 replay 或 labels；第 2 期起 `initial_state=None`，调用方必须传递上一期执行状态。BOM 和材料/产品映射在 shared 中固定。

`current_wafer_qty` 保留为既有预测模型的兼容特征，所选材料中该字段为 0。APP 的物料数量来自独立的 `fixed_quantity`（首次 dieQty）；不能把 dieQty 直接顶替已训练模型原来的 waferQty 特征。

“企业完工标签可用时间”和“回放收货发生时间”分开保存：训练拟合使用前者约束标签；已发生的模拟收货用于更新状态。不得把未来到货时间或“以后是否有标签”作为输入特征，也不能将所有有标签测试窗口等同于 APP 订单集合。

## 筛选结果与已知限制

原 CSV 有 803,546 条记录、11,332 个 Lot、225 个 woItem。所选三种材料有 186,146 条记录、3,873 个 Lot，全部为 root Lot，首次数量均为正 dieQty，材料映射稳定，无同 Lot 同时刻重复记录。完整重算确认左边界不完整历史为 **140** 个 Lot（之前讨论中的 139 为计数误差）；排除并保存明细后，数据集保留 **3,733 个 Lot、183,088 条快照**，含 3,704 个完工有标签 Lot 和 29 个末尾未确认 Lot。训练初期因此是所选合格批次的实验供给，不代表全厂完整供给。

| 集合 | 期间快照数 | 期间观测 Lot 数 | 决策时点订单行数 | 起点在途 Lot 数 | 已标注到货 Lot 数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 训练 | 113,542 | 2,344 | 1,951 | 0 | 2,195 |
| 验证 | 34,803 | 772 | 645 | 149 | 668 |
| 测试 | 34,724 | 870 | 660 | 104 | 841 |

决策订单行按“Lot＋周决策时点”计数；在两次决策之间出现并到货的 Lot 可以没有预测订单行，但仍保留新订单事件和实际到货。跨集合在途 Lot 可以重复出现，实际到货事件不重复。

测试的材料 A 需求隐含消耗约 1,215,263 die，初始库存、评价期内可用第一货源及最大第二货源合计只能覆盖约 **94.54%**，总量仍缺约 **66,343 die**。材料 B 同口径约 **105.23%**，材料 C 约 **196.34%**。这些是总量上限检查，期内时序和生产能力可能进一步限制生产；不据此修改测试需求或筛掉批次。积压允许存在，不能把供给不足等同于优化模型一定不可行。

测试末尾未确认问题沿用 [既有记录](daily_prediction.md)：B 的 9 个 Lot、38,173 die 在第 7 期期初已可见，保留在规划订单；C 的 20 个 Lot 均在该期期初之后首次出现，不能提前输入第 7 期决策。22 个 Lot、128,194 die 的第 7 期到货归属未确认，另 7 个 Lot、49,037 die 在 3 月 18 日仍有观测。不填造其到货日期或把未知当零。

在不计原材料库存成本和期末残值、当期到货下期使用的设定下，末期结局未知不直接改变前 7 期已执行成本口径；期末原材料库存及第一货源在途仍未完全核实。若延长执行期或增加相关库存/在途价值，应先补充结局信息。后续滚动实验按此口径记录成本，并保留末期库存上下界。

## 运行与验证

APP 求解器按用户指定选用本机 **CPLEX 12.8.0.0**，路径与接口选择另存于 [app_solver.yaml](../config/app_solver.yaml)，不改动冻结的数据集配置。2026-10-19 已通过命令行小型 LP 调用测试，解文件状态为 optimal、目标值为 -5，与手算一致。项目 Python 为 3.12.14，CPLEX 12.8 随附 Python 接口为 2.7/3.5/3.6，因此采用 Python 调用 `cplex.exe`、传入 LP 并读取 XML 解文件的方式。后续点 PTO 与历史商品周期基线各 7 次 APP 求解均为最优，详见 [滚动实验](app_pto_experiment.md)。

